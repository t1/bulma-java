== User Documentation

=== Overview

Bulma-Java is a server-side HTML library for Java that provides a type-safe, fluent API for generating HTML with Bulma CSS components.

Key principles:

* *Zero runtime dependencies* - The core library is pure Java
* *Fluent and chainable API* - No builders, no withers
* *Type-safe HTML generation* - Automatic HTML escaping for security
* *Framework-agnostic* - Works with JAX-RS, Spring, or any Java web framework

=== Quick Start

Simple example:

[source,java]
----
@Path("/")
public class Application {
    @GET
    @Produces(TEXT_HTML)
    public String index() {
        return html("Title Text").body(title("Hello World")).render();
    }
}
----

Returns:

[source,html]
----
<!DOCTYPE html>
<html lang="en">
    <head>
        <meta charset="utf-8">
        <meta http-equiv="X-UA-Compatible" content="IE=edge">
        <meta name="viewport" content="width=device-width, initial-scale=1">
        <title>Title Text</title>
    </head>
    <body>
        <h1 class="title">Hello World</h1>
    </body>
</html>
----

You can also return the `Renderable` directly and add a trivial `MessageBodyWriter`,
which we didn't include, as it depends on JAX-RS; analogous solutions could be written for Spring or whatever framework you use.

For more examples, look at the tests and the `all-tests.html` page generated by the tests.

For a demo application based on https://quarkus.io[Quarkus] and https://htmx.org/docs/[HTMX], see https://github.com/t1/htmx-quarkus-demo[htmx-quarkus-demo].

=== Usage Patterns

==== Static Imports

The API is designed around static imports. These are the main entry points:

[source,java]
----
import static com.github.t1.htmljava.HtmlBasics.*;  // div(), p(), h1(), span(), etc.
import static com.github.t1.htmljava.Html.html;      // html() for full documents
import static com.github.t1.htmljava.Anchor.a;       // a() for links
----

For Bulma components, import from the component classes:

[source,java]
----
import static com.github.t1.bulmajava.elements.Button.button;
import static com.github.t1.bulmajava.elements.Title.title;
import static com.github.t1.bulmajava.basic.IsModifier.*;  // PRIMARY, LARGE, etc.
----

==== Creating and Composing Elements

All element methods return the element itself for fluent chaining.
Content is added via `content()`, attributes via `attr()`, CSS classes via `classes()`:

[source,java]
----
div().id("main").classes("container").content(
    h1("Welcome"),
    p("Hello").classes("subtitle")
)
----

renders as:

[source,html]
----
<div id="main" class="container">
    <h1>Welcome</h1>
    <p class="subtitle">Hello</p>
</div>
----

==== Modifiers

Use `is()` and `not()` to toggle Bulma modifiers.
Modifiers are enums that map to CSS classes (e.g., `PRIMARY` → `is-primary`):

[source,java]
----
button("Submit").is(PRIMARY, LARGE)
----

renders as:

[source,html]
----
<button class="button is-primary is-large">Submit</button>
----

Don't use `.classes("is-primary")` — use `.is(PRIMARY)` instead, so the modifier can be toggled with `.not(PRIMARY)`.

==== Links

[source,java]
----
a("Click me").href("/target").title("Go there")
----

renders as:

[source,html]
----
<a href="/target" title="Go there">Click me</a>
----

==== Full Documents

`html()` creates a complete document with `<!DOCTYPE html>`, `<head>`, and `<body>`.
Content added to the document is automatically routed to the `<body>`:

[source,java]
----
html("Page Title")
    .stylesheet("app.css")
    .script("app.js")
    .body(div().content(p("Hello")))
----

Use `.head()` to add content to the `<head>` explicitly.

==== Security

All text content is automatically HTML-escaped. This is safe:

[source,java]
----
p(userInput) // <script> becomes &lt;script&gt;
----

To include trusted raw HTML (e.g., generated CSS or JavaScript), use `UnsafeString` or the `styleElement()`/`javaScriptCode()` methods on `Html`.
Never pass user-provided content through these unsafe methods.

=== Module Structure

This is a Maven multi-module project with three modules:

==== core (artifact: `java-html`)

Foundation library providing core HTML rendering capabilities.

* *Package:* `com.github.t1.htmljava`
* *Published to Maven Central*
* *Key classes:*
** `Renderable` - Core abstraction for anything that renders to HTML
** `Renderer` - StringBuilder-based HTML renderer with automatic indentation and escaping
** `AbstractElement<SELF>` - Base class for all HTML elements using generic self-type pattern
** `EventHandlers<SELF>` - Mixin interface for HTML event handler attributes (`onclick`, `onkeyup`, etc.)
** `Modifier` - Interface for applying/unapplying modifications (classes, attributes)
** `HtmlBasics` - Static factory methods for common HTML elements

==== bulma (artifact: `bulma-java`)

Bulma CSS framework components implemented as Java classes.

* *Package:* `com.github.t1.bulmajava`
* *Depends on:* `java-html`
* *Published to Maven Central*
* *Organized into subpackages:*
** `basic` - Base classes and modifiers (`BulmaElement`, `IsModifier`, `HasModifier`, enums)
** `elements` - Bulma elements (`Button`, `Icon`, `Table`, `Tag`, `Title`, etc.)
** `components` - Complex components (`Card`, `Modal`, `Navbar`, `Menu`, `Dropdown`, etc.)
** `form` - Form controls (`Form`, `Field`, `Input`, `Select`, `Checkbox`, etc.)
** `layout` - Layout components (`Section`, `Container`, `Hero`, `Footer`, etc.)
** `columns` - Bulma column grid system

==== forms-test (artifact: `bulma-java-forms-test`)

Demo/integration test application using Quarkus.

* *NOT published to Maven Central* (deployment skipped in pom.xml)
* *Uses Java 21* (core modules use Java 17)
* Demonstrates real-world usage with JAX-RS, HTMX, and bean validation
* Example patterns: Customer/Product/Order management

=== Architecture

==== Fluent API Implementation

The fluent API uses the *generic self-type pattern*:

[source,java]
----
public class AbstractElement<SELF extends AbstractElement<?>> {
    @SuppressWarnings("unchecked")
    protected SELF self() { return (SELF) this; }

    public SELF content(String text) {
        // ... add content
        return self();
    }
}
----

All element classes use `@SuperBuilder(toBuilder = true)` from Lombok internally for cloning (`twin()`), but the public API is purely fluent — no builders. Every modification method returns `SELF` for chaining.

==== Modifier System

Modifiers implement apply/unapply/check operations and are applied via `is()` and `not()` methods:

[source,java]
----
button("Click me").is(PRIMARY, LARGE)
----

Hierarchy:

* `Modifier` interface
** `ClassModifier` - Operates on CSS classes
*** `PrefixedClassModifier` - Generates "prefix-name" classes
**** `IsModifier` - Generates "is-*" classes (Bulma)
**** `HasModifier` - Generates "has-*" classes (Bulma)
** `AttributeModifier` - Operates on attributes

==== HTML Rendering

Two-phase process:

1. *Build Phase* - Construct element tree using fluent API
2. *Render Phase* - Walk tree and generate HTML string

Key rendering features:

* Automatic HTML escaping via `Renderer.safeAppend()`
* Unsafe mode via `unsafeAppend()` for trusted HTML
* Pretty-printing with automatic indentation tracking
* Separate-line rendering for block vs inline elements
* Self-closing tags for void elements like `<input />`

==== Field Component Pattern

The `Field` class demonstrates complex component composition:

* Maintains internal list of `FieldControl` objects
* Each control tracks: content, left/right icons, left/right addons, help text
* On render, constructs proper nested HTML structure
* Automatically wraps content in `<div class="control">`
* Moves modifiers between elements (e.g., `EXPANDED` from input to control)

=== Testing Approach

==== Core/Bulma Testing

Tests use direct string comparison with custom assertions:

[source,java]
----
then(element).rendersAs("""
    <div class="field">
        <label class="label">Label</label>
    </div>
    """);
----

The `RenderTestExtension` aggregates all test output into `bulma/target/all-tests.html` for visual inspection. This file includes full Bulma CSS and renders every test case, making it easy to verify visual appearance.

When running tests, you can set `-DBULMA_JAVA_OFFLINE=true` to load Bulma/FontAwesome from a local forms-test instance at localhost:8080 instead of CDN.

=== Coding Conventions

==== Naming

* Static factory methods: lowercase (e.g., `field()`, `input()`, `button()`)
* Modifiers: UPPERCASE enums or constants (e.g., `PRIMARY`, `LARGE`)
* Fluent methods: return `SELF` type for chaining

==== Content Management

* Content stored as `Renderable` (single) or `ConcatenatedRenderable` (multiple)
* `content()` automatically merges into concatenated list
* Can insert at specific index: `content(element, 0)` for prepending

==== Security

* Always use safe methods for user-provided content
* HTML escaping is automatic via `Renderer.safeAppend()`
* Only use `unsafeAppend()` or `UnsafeString` for trusted HTML
